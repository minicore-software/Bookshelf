## [Unreleased]

### Added
- `CLAUDE.md` project base: build commands, architecture, domain model, and tech stack.
- `README.md` project overview: purpose, features, and getting started.
- `CHANGELOG.md` to track notable changes going forward.
- Product design canvas in [`project/`](project): Library, Book Detail, Discover & Add,
  Update Progress, Reading Stats, Settings, Lend a Book, and My Loans screens.
- Android project scaffold: app module with Hilt, Room, and Navigation Compose wiring,
  and the Gradle 9.8.2 wrapper.
- Adaptive launcher icon (`ic_launcher`/`ic_launcher_round`) generated from
  `resources/icon.svg`, plus the `tools/launcher-icon` generator/fitness-function script
  (`npm run generate` / `npm run check`).
- Two-stage cold-start splash screen: the system splash shows the adaptive launcher
  icon on a paper background instantly, then a full-bleed Compose splash shows the
  converted `resources/splash-screen.svg` artwork for 600ms before the app's nav
  graph appears, with no fallback path needed below API 31. Density-bucketed splash
  artwork is generated by the new `tools/splash-screen` script (`npm run generate` /
  `npm run check`), rendered with a pinned Playfair Display Bold (OFL) font.
- Blank landing screen: a `core/designsystem/` package (`BookshelfTheme`, light-only,
  paper/ink/forest colours) and the `features/library/ui/LibraryScreen.kt` screen,
  showing a centered "Bookshelf" title set in a bundled, static Fraunces SemiBold
  font, now wired as the app's real `Home` start destination. `MainActivity` applies
  `BookshelfTheme` and forces dark status/nav bar icons regardless of system theme.
  The static Fraunces cut is built from the upstream variable font by the new
  reproducible `tools/fraunces-font/generate.py` script (`generate` / `check`),
  pinned to a source commit and fonttools version, with its OFL license bundled
  under `app/src/main/assets/licenses/`. Closes out epic #6 (App Bootstrap).
- Book/Loan Room schema (`core/model`, `core/database/{entity,converter,dao}`): `BookEntity`
  and `LoanEntity` tables matching the domain model, with `Instant`/`LocalDate`
  (epoch-day)/`BookStatus` (stable `want_to_read`/`reading`/`finished` strings) type
  converters. At most one open loan (`returned_at IS NULL`) per book is enforced by two
  SQLite triggers recreated on every database open ([ADR-001](docs/adr/ADR-001-Model-Book-And-Loan-Tables-With-Trigger-Enforced-Open-Loan.md)), and `loans.book_id` cascades on
  book delete. Replaces the scaffold `PlaceholderEntity`; schema stays at version 1. A
  read-only `LibraryRepository`/`RoomLibraryRepository` (`features/library/{domain,data}`)
  exposes all books, per-status books, lent-out books (joined with borrower/due date) and
  per-status + lent-out counts, for the Library screen epic (#17) to build on. **Existing
  debug installs must be uninstalled once** before installing this build: the schema's
  identity hash changed, so Room throws on open instead of migrating. (#18)
- Library header wordmark: a Compose-built header replacing the placeholder
  "Bookshelf" title — a `BrandMark` tile, the Fraunces "Bookshelf" title, and an
  Inter tagline, plus a search bar styled as a clickable, no-op `Row` (not a
  real `TextField`) matching the design reference. New `ink_muted`/
  `paper_bright`/`line` colour tokens in `core/designsystem/`. Bundles a new
  static Inter Regular font (`app/src/main/res/font/inter_regular.ttf`) with
  its SIL OFL 1.1 license under `app/src/main/assets/licenses/`. Closes #10.
- Currently-reading and lent-out rows on the Library screen: a stateful
  `LibraryRoute`/`LibraryViewModel` observes the new `ObserveLibraryRowsUseCase`
  (combining #18's `LibraryRepository` flows with a midnight-rolling
  `CurrentDateProvider`) and renders two horizontally scrollable rows —
  "Currently reading" (cover + title only, no progress UI) and "Lent out"
  (dimmed cover, borrower, colour- and weight-coded "Due in N days" /
  "Overdue N days" caption, "See all · N"). Adds a shared `BookCover`
  placeholder component (`core/designsystem/component/`, palette-by-ID
  colour blocks — no image-loading library yet, since no screen writes
  `coverUri`), new `LoanDueStatus` domain logic for the due/overdue
  boundaries, library-row colour and Inter SemiBold type tokens, and Hilt
  instrumented-test infrastructure (`HiltTestRunner`, `HiltTestActivity`)
  so `BookshelfNavGraphTest`/`MainActivityLaunchTest` can inject a fake
  repository. Both card taps and "See all" are no-ops for now (Book Detail
  and My Loans ship in later tickets). (#20)
- Library grid and filter chips: a 3-column book grid below the existing
  rows, preceded by a single-choice chip row ("All", "Reading", "Finished",
  "Want to read", "Lent out") showing live counts from `LibraryRepository`.
  Selecting a chip re-queries the matching repository flow — the "Lent out"
  chip uses the open-loan join, never a book's own status — and restores
  the selection across rotation and process death via `SavedStateHandle`. Each
  grid card shows the cover (a new `BookCover` `Grid` variant with no title
  overlay), title, a colour-coded status dot (reading/finished/want-to-read/
  lent, the lent dot overlaying the status as a hollow terracotta ring), and a
  "Lent to <borrower>" caption for books with an open loan, with merged
  accessible semantics read in title/status/loan order. Card taps remain
  no-ops (Book Detail ships later). (#21)
- Empty-state Library screen: when the library has 0 books, the
  currently-reading row, lent-out row, filter chips and grid are hidden
  (already true after #20/#21) and an "An empty shelf" panel - heading,
  body copy, existing paper/forest/ink-muted tokens, no new illustration -
  is shown in their place. A new "Add a book" `FloatingActionButton`
  (bottom-right, forest fill, hand-drawn plus glyph) is now always visible
  across loading, empty and populated states as a stub; tapping it is a
  no-op (`onAddBookClick` hoisted through `LibraryRoute` to
  `BookshelfNavGraph`, wired up for real once Add Book ships). New
  `LibraryEmptyState`/`LibraryAddBookFab` composables and an
  `isLibraryEmpty` predicate on `LibraryUiState.Content`, plus Compose UI
  tests covering the 0-book state end-to-end (fresh-empty,
  empty-to-populated, and populated-to-empty via deletion), cold-start
  loading flash, FAB double-tap, and 2x font scale on a narrow/short
  screen. (#22)
- Add a book manually: tapping the Library FAB now opens a bottom-anchored
  sheet (`AddBookRoute`/`BookForm`, a Navigation `dialog` destination reached
  only through `navigateToAddBook()`) with Title (required), Author, Year
  (digits-only stepper field), a 1-5 star rating (unset is a distinct third
  state from 1 star, tap-to-clear), a short comment, and a preset-colour
  cover swatch picker. Saving always persists `status = want_to_read`
  (`AddBookUseCase`, `core/coverimage/CoverImageStore`), with title/author
  trimmed and a blank comment stored as `null`. Cancel, the close button,
  system back and a scrim tap all discard the draft; a dirty draft asks
  "Discard this book?" first. Saving is single-flight, so a double tap
  cannot create two books. The cover can also be an uploaded photo: "Upload
  an image..." launches the system Photo Picker, the picked image is
  downscaled, EXIF-stripped and stored as an app-private JPEG
  (`CoverImageStore`/`FileCoverImageStore`, ADR-003), and a set image shows
  a live thumbnail with Replace/Remove actions - swatches stay tappable and
  immediately replace an image with no confirmation. `BookCover` now draws
  that stored image wherever a cover shows (library rows/grid), falling
  back to the id-derived colour placeholder while loading or on failure.
  An uploaded photo is only committed to storage after a successful save,
  with the file rolled back if the database insert fails, so a retry never
  leaves an orphaned image or silently loses the picked photo. Saving
  shows "Added to your shelf" as a Snackbar back on the Library, every
  time a book is saved in the session. (#31)

### Changed
- **Internal, no end-user-visible change:** extended the `books` table (Room
  schema 1 → 2) with nullable `comment`, `memory_why`, `memory_where`,
  `memory_what` and `cover_color` columns, migrated via a hand-written
  `Migration(1, 2)` that backfills existing rows' `cover_color` to a
  deterministic preset key so covers render identically to before the
  upgrade. Two SQLite triggers (insert and update, registered on fresh
  installs and inside the migration for upgraded ones) now enforce that a
  book never has both a cover image and a cover colour at once. Introduces
  a sealed `Cover` domain type (`Image`/`Preset`) replacing the old
  `Book.coverUri` string, and extends `LibraryRepository` with
  `observeBook`, `addBook` and `updateBook` for upcoming Book Management
  screens (#31–#35) to build on. See
  [ADR-002](docs/adr/ADR-002-Store-Book-Cover-As-Uri-Or-Preset-Key-With-Trigger-Enforced-Exclusivity.md).
  (#30)

Git does not track empty directories. The three `features/library/*` packages each get a `.gitkeep` so they survive the commit. No dummy Kotlin classes go there. `core/` and `di/` hold real files.

**`navigation/` sits next to `MainActivity` at the root**, the same way Cartio does it. It does not go under `core/`. The nav graph imports feature screens, so putting it in `core` would make `core` depend on `features`, which reverses the dependency direction. `CLAUDE.md`'s tree does not list it yet, so the developer adds `navigation/` and the root `BookshelfApp.kt`/`MainActivity.kt` to the tree in `CLAUDE.md` in the same PR. That keeps the "package layout matches CLAUDE.md" AC true in both directions.

## 5. Room: the "empty `@Database`" AC needs one entity

**Fact (checked in `room-compiler-2.8.5.jar`):** Room's `DatabaseProcessor` fails with `@Database annotation must specify list of entities` when the entities list is empty. A literally empty `@Database(entities = [])` will not compile, so the AC "An empty `@Database` Room class compiles" has to mean: no feature entities and no DAOs, but Room's annotation processor runs and generates `BookshelfDatabase_Impl`.

**Design:**
- `core/database/entity/PlaceholderEntity.kt` is a single `@Entity(tableName = "scaffold_placeholder")` with one `@PrimaryKey val id: Int`. A KDoc says it exists only so Room accepts the database, and that it gets removed by the first ticket that adds a real entity.
- `core/database/BookshelfDatabase.kt` is `@Database(entities = [PlaceholderEntity::class], version = 1, exportSchema = true) abstract class BookshelfDatabase : RoomDatabase()`. It has no DAOs and no `@TypeConverters` yet.
- `di/DatabaseModule.kt` follows Cartio's shape. It is an `object` in `SingletonComponent` with `DATABASE_NAME = "bookshelf.db"` and a `@Provides @Singleton fun provideDatabase(@ApplicationContext context): BookshelfDatabase` that uses `Room.databaseBuilder(...).build()`. It has no migrations and no destructive fallback. Nothing injects the database yet, so it is never opened at runtime. Hilt still checks the binding at compile time, which proves Room and Hilt work together.
- Commit `app/schemas/.../1.json`.

**Rule for the first real-entity ticket (the library `Book` entity):** if no build has been distributed to anyone by then (this epic only produces local debug builds), replace `PlaceholderEntity`, keep `version = 1` and regenerate `1.json`. Developers uninstall their debug build. If a build has been distributed, bump to `version = 2` with an `@AutoMigration` and `@DeleteTable(tableName = "scaffold_placeholder")`. Record this rule in the PR description so the next ticket picks it up.

Alternatives considered:
- *Add the real `Book` entity now.* That is a scope leak into the library feature, and it fixes data-model choices (status enum storage, nullable fields, indices) without a ticket.
- *Keep `@Database` off until a feature needs it.* That fails the AC and D11.
- *Use `exportSchema = false` to avoid committing a placeholder schema.* That diverges from Cartio and from the `room.schemaLocation` arg in `CLAUDE.md`, and someone has to remember to turn it back on.

## 6. Hilt, activity, navigation

- **`BookshelfApp`**: `@HiltAndroidApp class BookshelfApp : Application()` with no body. Registered with `android:name=".BookshelfApp"`.
- **`MainActivity`**: `@AndroidEntryPoint class MainActivity : ComponentActivity()`. `onCreate` calls `super.onCreate`, then `enableEdgeToEdge()`, then `setContent { MaterialTheme { Surface(Modifier.fillMaxSize()) { BookshelfNavGraph(rememberNavController()) } } }`. Don't call `installSplashScreen()` (that's #9) and don't add a custom theme composable (that's #10). The plain `MaterialTheme` wrapper gets replaced by #10's `BookshelfTheme`.
- **`BookshelfDestinations`**: `sealed class BookshelfDestinations(val route: String)` with one `data object Home : BookshelfDestinations("home")`. String routes match Cartio. Type-safe `@Serializable` routes are the alternative, but they need the kotlinx-serialization plugin and library, which are not in `CLAUDE.md`'s stack. Not worth adding for one route.
- **`BookshelfNavGraph(navController: NavHostController)`**: `NavHost(navController, startDestination = BookshelfDestinations.Home.route) { composable(Home.route) { PlaceholderHomeScreen() } }`. `PlaceholderHomeScreen` is a `private` composable in the same file. It shows `Text(stringResource(R.string.app_name))` centered, with `Modifier.safeDrawingPadding()` so edge-to-edge doesn't put it under the status bar. #10 replaces it with the real landing screen, which lives in its own feature package.
- `MainActivity` keeps no state that would need `rememberSaveable` yet.

## 7. Manifest and resources

- **`AndroidManifest.xml`**: `<application android:name=".BookshelfApp" android:label="@string/app_name" android:theme="@style/Theme.Bookshelf" android:allowBackup="true" android:fullBackupContent="@xml/backup_rules" android:dataExtractionRules="@xml/data_extraction_rules" android:supportsRtl="true">` and one `<activity android:name=".MainActivity" android:exported="true">` with the MAIN/LAUNCHER intent filter.
  - Leave out `android:icon`/`android:roundIcon`. The system default icon shows until #8 adds them.
  - No `<uses-permission>` entries. The app needs no permissions yet, and the INTERNET/CAMERA permissions come with the features that use them.
  - No `android:screenOrientation`, no `android:resizeableActivity="false"` (D13). "Phone-only" here only means we don't build tablet layouts. We don't block tablets in the manifest or with `<supports-screens>`.
- **`themes.xml`**: `<style name="Theme.Bookshelf" parent="Theme.Material3.Light.NoActionBar" />`. Cartio uses `DayNight`. Bookshelf's design only defines a light paper palette, so using `Light` avoids a dark window background flashing before #10's theme loads. #9 adds `Theme.Bookshelf.Splash` with `postSplashScreenTheme = Theme.Bookshelf`.
- **`strings.xml`**: `app_name` = `Bookshelf`.
- **Backup XMLs**: same shape as Cartio. Include `domain="database" path="bookshelf.db"` in `full-backup-content`, `cloud-backup` and `device-transfer`, and nothing else. `bookshelf.db` must match `DatabaseModule.DATABASE_NAME`.

## 8. Test strategy

| AC | How it's verified | Level |
|---|---|---|
| `./gradlew assembleDebug` succeeds | Run on a clean checkout with `local.properties` absent or pointing at an SDK with platform 37.2 installed | Build |
| App installs and launches | `./gradlew installDebug`, then launch from the launcher with the default icon, label "Bookshelf". No crash. The placeholder text shows. Check `adb logcat` for no Hilt/Room errors. Optionally, automated: `MainActivityLaunchTest` uses `ActivityScenario.launch(MainActivity::class.java)` and asserts the state reaches `RESUMED`. That proves Hilt injection works at runtime, using only dependencies already in the table. | Manual + optional instrumented |
| Package layout matches CLAUDE.md | Reviewer compares the tree with section 2 and the updated `CLAUDE.md` tree, and checks that the `.gitkeep` files are committed | Review |
| `@HiltAndroidApp` present and component generates | `assembleDebug` passes and `Hilt_BookshelfApp` / `Hilt_MainActivity` are generated (KSP output under `app/build/generated/ksp`) | Build |
| Empty `@Database` compiles | `BookshelfDatabase_Impl` is generated and `app/schemas/.../1.json` exists. Optionally, automated: `BookshelfDatabaseTest` opens `Room.inMemoryDatabaseBuilder(context, BookshelfDatabase::class.java).build()`, gets `openHelper.writableDatabase`, and closes it | Build + optional instrumented |
| NavHost with at least one route | Manual launch shows the placeholder. Code review confirms `startDestination` is registered. | Manual + review |

`./gradlew test` should pass, possibly with no tests at all. Don't add the template "ExampleUnitTest" boilerplate. The two optional instrumented tests are cheap and get reused by #9 and #10, so add them if the developer has an emulator available.

Failure modes worth checking:
- **Missing SDK platform 37 minor 2 or wrong JDK.** The build fails before any project code runs. Gradle's daemon toolchain 21 via foojay should provision the JDK, so the SDK is the more likely gap.
- **KSP/Kotlin/AGP mismatch.** Hilt or Room generated code is missing, or KSP fails to apply. Use exactly Cartio's versions, which are known to work together.
- **`gradlew` committed with CRLF endings or without the executable bit.** It breaks on macOS, Linux and CI later. The repo has no `.gitattributes`. Check with `git ls-files --eol gradlew` and use `git update-index --chmod=+x gradlew`.
- **Schema JSON not committed, or `app/schemas` ignored.** Nothing would catch future schema drift.
- **Cold-start crash because of the theme.** A `ComponentActivity` with a Material3 XML theme needs the `material` dependency. A missing dependency shows up as resource-linking errors at build time.
